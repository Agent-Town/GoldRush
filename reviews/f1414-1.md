## What it does

Two things, both parity corrections between `src/sim/HeadlessContractSim.ts` and the game:

1. **The secure gate.** `HeadlessContractSim.ts:225` now withholds auto-secure while a contract
   declares `twist.baron` and the baron is unbeaten. This is not new behaviour — it is what
   `src/game/Game.ts:4673-4679` (`autoSecureWaveForRun` → `waitsForBaronDefeat()`, `:4709-4714`)
   has always done in the real game, **on clean main, untouched by this slice**. The headless sim
   was the one that was wrong: it auto-secured at `secureWave` whether or not the boss was alive.
2. **The defeat predicate.** A component boss (a boss spawned as N destructible parts) now flips
   `baronBeaten` when its last part dies, keyed on the contract's declared `bossKind` **and** the
   exact group id `WaveSystem` built **and** `bossRemaining === 0`.

Plus the `escortsSpawned` threading through `WaveSystem.spawnBaronWave` → `onBaronSpawned`, and two
new bench seeds (`e1-baron-04`, `e1-baron-05`).

## Findings

**F-1415-1 — the component branch of the new predicate has no test. (open, corrective owed)**
`scripts/gr-sim.test.mjs`'s new baron test covers the **plain-baron** path only (`e1-baron`:
`secured: true`, one `baron_defeated`, rocket telegraph/volley, the escorts-capped case). The
component path — `bossGroupId` match + `bossRemaining === 0` — is exercised by **no test**. The only
evidence it fires is the run's "high-power Hill Mine diagnostic" (component remaining `2 → 1 → 0`,
secured at wave 12, exactly one defeat event), which was **not preserved as anything runnable**.
This fire verified the predicate's group-id link by reading (above), which is why the merge stands;
but a read is not a guard. Blast radius if it is wrong: headless `e2-hill-mine` runs never secure —
no pinned bench asserts them, and the game path is untouched. Corrective: a test that spawns the
railcar group and kills its three parts. **Owed, fire-authorable.**

**F-1415-2 — the "escort canary" was never a canary; its expected green encoded the divergence.**
Two consecutive main-slot runs (`f1413-1`, `f1414-1`) STOPPED on
`node scripts/gr-sim.mjs --contract e2-hill-mine --mode escort --policy=idle` staying rc 1. That
command appears in **no test file**. The pinned escort test is
`scripts/gr-sim.test.mjs:89`, and it asserts only that the CLI is not signal-killed
(`assert.equal(cli.signal, null)` — rc 1 passes that) and that the first stdout line carries
`modes[0].id === 'escort'`. It has **never** asserted `rc 0` or `secured`. The green the masters
demanded — `secured: true` at wave 12, `fnv1a32:5ad506eb` — was the **pre-graft** sim auto-securing
past a live Armored Railcar, i.e. the very divergence this slice cures. Under `--policy=idle` the
driver issues no orders, so it can never kill a 3-part boss at `hpScale: 30`; the run then survives
past the F-1401-1 harness ceiling and exits 1. **That is the correct outcome and it must not be
"fixed".** The run itself saw this clearly and refused to add a headless-only escort bypass — its
words: *"such a bypass would hide the production behavior difference rather than prove the requested
component-destruction cure."* It was right to refuse; it was wrong only about what that implied for
the merge. Ruling: **the probe is retired as an acceptance test.** Do not re-open this hunt.
