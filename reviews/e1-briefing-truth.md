**F-1068-2 — `fallbackReason: 'debug-disabled'` on an ordinary no-`?debug` boot.** ✓ VERIFIED by reading the path, not by inference:

- `src/meta/ContractFamilies.ts:1148` sets `fallbackReason = 'debug-disabled'` only when `requestedId && !debug && !launched && !liveSagaFlagship`.
- `launched` comes from `isPlayerContractLaunch(id)` (`:1208`), which is **`sessionStorage.getItem(PLAYER_CONTRACT_LAUNCH_KEY) === id`** (`:1210`).
- The key is written by `stagePlayerContractLaunch()` (`:1074`, `sessionStorage.setItem`, `:1078`).
- Its caller is `launchContract()` (`src/main.ts:213-221`), which stages the key and then calls **`window.location.reload()`** (`:220`) — a real navigation.

The deciding line is the harness's, not the engine's: `seedProfile()` installed a Playwright `addInitScript` containing **`sessionStorage.clear()`**. `addInitScript` re-executes on *every* navigation, so on the post-click reload it wiped `PLAYER_CONTRACT_LAUNCH_KEY` **before the app booted and read it** — manufacturing `launched === false`, hence `'debug-disabled'`, in the test and nowhere else. Deleting that one line is the correct repair; the engine never had the defect. The sibling helper `clearStorage()` (`:143`) keeps its `sessionStorage.clear()`, and correctly so — its tests navigate straight to `/?debug&contract=…`, where `debug` short-circuits the launch-key check.

**F-1068-3 — `e1-baron` card `data-contract-locked="true"` where the spec expects unlocked.** ✓ VERIFIED at `src/meta/ContractUnlock.ts:48-54`: `e1-baron`'s rule is `science-complete+2-secured`, requiring science complete **and** `securedContracts.size >= 2` — **two distinct secured contract ids**. The fixture seeded exactly one (`the-claim`), so the engine locked the card **correctly**. The spec's `UNLOCKED_BOARD_CONTRACTS` set (`:104`) asserts all five E1 contracts are open, which is only true for a player who has genuinely earned the whole board. Seeding a second secured claim (`e1-dry-gulch`) makes the fixture model that player. This is a precondition repair, not a fudged expectation: the unlock rule is untouched, and the other rungs stay coherent (`e1-dry-gulch` = `wave10OnClaim`, `e1-twin-banks` = `firstSecuredClaim`, `e1-night-shift` = `science≥3`).
