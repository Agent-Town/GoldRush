### The convergence hole is closed by construction, not by a lucky measurement

The run reported eight approaches all aimed at `(-9.000, 6.700)` landing `0.046–0.084` out. That is a good number, but a reported number from one run is not what makes this merge safe. Reading the helper is:

`moveHeroTo` can only `return` through its `Math.hypot(dx, dz) <= 0.12` branch (`e2e/helpers/hero-approach.ts:16-18`). Every other exit — the 15 s progress timeout, a `'blocked'` sampler result, or exhausting all 12 attempts — `break`s the loop and falls through to `throw new Error(...)` at `:58`. **Therefore a passing test now entails that every approach converged inside tolerance.** The old implementation had no such property: its `pressUntil` returned unconditionally once a per-axis threshold was crossed, so it could and did return while >2 units off. s1256's "passing by luck" failure mode is not merely absent from this run — it is no longer expressible.

## Findings
