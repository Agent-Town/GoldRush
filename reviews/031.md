## Findings
- **F-1 (fixed inline, test-only, ~18 lines):** 031's own spec drove the hero purely via the mouse-simulated touch stick (`page.mouse` on `#touch-stick`). On the touch-emulated `mobile-chrome` (Pixel 5) project this does NOT move the hero — the stick uses `pointerdown/move` and Playwright's mouse doesn't drive it there — so the default generated **walk** sprite never activates and `waitForSprite(frameCount>=2)` timed out. Verified root cause: post-`startStick` mobile snapshot = `clip:"idle", frameCount:1`. Product code is correct (green on desktop; real mobile touch works for users). Fix: `startStick`/`releaseStick` now also hold/release the matching WASD keys (`readMovement` sums keyVector + pointer, viewport-independent). Both projects green after.
