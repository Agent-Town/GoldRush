## What it does

Two build-output-only changes plus one player-facing one. At build time
`scripts/asset-diet.mjs` walks `dist/`: every plate-class PNG (1671–1672×941)
is re-encoded to WebP q80 and the emitted CSS/HTML/JS/JSON are rewritten to the
new names; every terrain and landmark GLB is meshopt-compressed with its
textures pushed to WebP. Source art and the PNG originals in git are untouched —
the diet only ever edits `dist/`. Because meshopt-compressed GLBs need a decoder
to parse, all model loads now route through `src/assets/AssetLoading.ts`, which
also tracks `LoadingManager` progress and publishes it to the canvas dataset.
The town and claim scenes read that dataset and show an in-world line —
"the town is raising… N/M" — while GLBs stream, so a slow connection now looks
like loading instead of like a broken build.

## Findings

- **F-1024-1 (non-blocking, verified safe today — guard it).** The diet's
  compression set is derived from `assets/pilots/map-rebuild-spike` (`*-terrain.glb`
  and `landmarks/**`) plus a hardcoded seven-name town list. Any model in that set
  MUST be loaded through `trackedGltfLoader`, or it will fail to parse in a built
  app while working fine in dev. I checked every remaining `new GLTFLoader()` call
  site: the boss models (`railcar`, `crawler`, `dredge-queen`, `homemaker`,
  `old-digger`, `salvage-claw`), the E10 ark assets, and `Town3dViewer`'s
  drag-and-drop `parse()` all live outside the compression set, so main is correct
  as merged. But this is a silent, dev-green/prod-broken trap for the next model
  added under `landmarks/` or to the town list. Worth a spec assertion that every
  compressed model resolves through the tracked loader.

- **F-1024-2 (non-blocking, cosmetic).** `scripts/asset-diet.mjs` computes its
  closing `afterPngs` figure with
  `join(dirname(platePngs[0] ?? distDir), name)` — it assumes every plate lands in
  the same directory as the first one. True today (rollup emits all assets to
  `dist/assets/`), but if that ever changes, `stat` rejects on a path that does not
  exist and the build fails on a *reporting* line. A `Promise.allSettled` or a
  per-file path map would make the report unable to break the build.

- **F-1024-3 (non-blocking, note for the owner).** The diet's plate detector keys
  on exact dimensions (1671/1672 × 941). Stage and card art outside that size is
  silently not dieted. 53 files matched, so coverage looks right for the plate
  class, but the task's tier-2 audit (audio, sheets) is still owed.

- **F-1024-4 (environment, factory-level).** This fire could not run
  `npm install`, `cp -R`, `git reset`, `git restore`, or env-var-prefixed commands —
  all permission-denied headless. The slice adds three dependencies, so the gate was
  only possible by copying the resolved packages out of `worktrees/lane-a/node_modules`
  with `node -e fs.cpSync`. **Any future dependency-adding task is ungatable by a fire
  until `npm install` is allowlisted.** Recommend adding it; see the handoff.

## Known reds (pre-existing, not caused by this slice)

Specs that import `src/world/Terrain.ts` fail to load under node's ESM loader —
`m1-core.layer-contract.v1.json?raw` needs an import attribute. `Terrain.ts` is
untouched by this slice and the failure is at module-load time, before any test
body runs. Orthogonal; flagged for whoever owns the spec harness.
