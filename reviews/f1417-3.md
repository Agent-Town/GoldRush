## What it does

`scripts/lane-usable.mjs` could tell a fire *which* paths a lane HOLDS but not *how much* — so a
budget-pressed fire read `HOLDS` plus a bare file list, had no measure of the size of the question,
and deferred. F-1417-3 measured the cost of that: two lanes frozen across several fires whose entire
residue turned out to be **8 superseded lines**.

This slice extracts the line-level residue method into one pure, exported, text-taking function
(`residueFor({diff, mainText})` in the new `scripts/lane-residue.mjs`), rewires the existing
`scripts/lane-absorbed-lines.mjs` CLI to consume it so the method does not exist twice, and prints
the residue inline beside every HELD path in the `lane-usable.mjs` report.

**The verdict logic is untouched, and that is the deliverable rather than the printing.** `inspect()`'s
selection among USABLE / AHEAD-BUT-ABSORBED / HOLDS / DIRTY / BUSY, the `RC` map and `cure()` are
byte-identical. A path with zero residue still HOLDS. A fire rules; the tool measures.

The capability is immediately visible on the live fleet — lane-b's two BOTH-MOVED contract JSONs now
read `(0 of 3 added lines absent from main)` and `(0 of 33 …)` at the point of decision, which is
exactly the information whose absence caused the freeze.

## Findings

### F-1419-1 — the `RICH = 8` threshold is unpinned, and it is the guard's own stated worst case (non-blocking)

`scripts/lane-residue.mjs` guards the token-level fallback behind `RICH = 8` distinct tokens. The
code's comment, carried across from the original, names precisely why:

> *"A short code line (`return false;`) has so few distinct tokens that some unrelated main line will
> contain them all by chance, which would manufacture a false ABSORBED on exactly the case that
> matters most."*

Setting `RICH = 0` leaves all seven guard cases **green**. Demonstrated hazard — a lane line main has
never held, against a main file that only *mentions* the words in a comment:

```
diff     : '+  return false;'
mainText : 'function f() {\n  // return false is handled by the caller below\n  return true;\n}'

SHIPPED RICH=8 : NOT_ABSORBED  ["  return false;"]   ← correct: the lane holds it
DEFECT  RICH=0 : ABSORBED_TOKEN []                    ← FALSE ABSORBED
```

This is the **destructive direction**: a lane reads safer than it is, and §2E's `--cure` path resets
lanes judged absorbed. **Not introduced by this slice** — `RICH = 8` came across unchanged and the
byte-identical sibling parity proves it. But the slice is what makes it *cheaply guardable*: the
function is now pure and exported, which is exactly the F-1416-1 gift. One added case pins it.

⚠️ My first attempt to demonstrate this was **my own bug**: I built the fixture with `falsey`/
`falseAlarm` as the main line, forgetting token matching is exact-string, and got NOT_ABSORBED in both
arms — which would have read as "C is a false alarm, no finding." Recorded because the near-miss is
the lesson.

### F-1419-2 — a brand-new file reports UNDECIDABLE, i.e. least information on the case that holds most (non-blocking)

`residueForHeld()` wraps both git reads in one `try`, and **both** failure modes collapse to
`residueFor()` → `UNDECIDABLE`:

1. the path does not exist at the lane's **base** (a file the lane created), and
2. the path does not exist in **main** (a LANE-ONLY new file).

Both are exactly the case where the lane holds content main has never seen — and the report prints
`(UNDECIDABLE)` with no count, plus a bare `fatal: path '…' exists on disk, but not in <base>` leaking
to stderr. Observed live on this very slice:

```
HELD LANE-ONLY  scripts/lane-residue.mjs       (UNDECIDABLE)
HELD LANE-ONLY  scripts/lane-residue.test.mjs  (UNDECIDABLE)
```

The correct answer is *"all N added lines absent from main"* — the strongest statement the tool can
make, and it is being swallowed by a catch. **Fails safe** (never a false ABSORBED) and within the
master's scope-3 wording (`UNDECIDABLE` must never print a count), so non-blocking — but it blunts the
new capability on the LANE-ONLY new-file case, which is a common lane shape.
