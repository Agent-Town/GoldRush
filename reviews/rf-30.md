## What it does

rf-29 (`46db455c`) closed the last hardcoded port in `scripts/probe-plain-boot-console.mjs`. Its
first test was named `rejects an unset PROBE_BASE before launching a browser` and its goal leaf
listed resolve-before-launch as a deliverable — but the body asserted only `status !== 0` and
`stderr =~ /PROBE_BASE/`, **neither of which is sensitive to ordering**. s1091 measured that:
moving `chromium.launch()` above the resolve left the guard 2/2 GREEN while a browser leaked
before every throw.

This slice adds **exactly one test, +10 lines, one file**. It takes scope 2 (the environment
sabotage) — the 2b dynamic-import fallback was **not** needed and the shipped script has **zero
diff**:

```js
test('rejects an unset PROBE_BASE before checking the browser executable', () => {
  const result = spawnSync(process.execPath, [SCRIPT], {
    env: { ...envWithoutBase, PLAYWRIGHT_BROWSERS_PATH: '/nonexistent-lane-probe-launch-ordering-1091' },
    encoding: 'utf8',
  });
  assert.ok(Number.isInteger(result.status) && result.status !== 0, result.stderr);
  assert.match(result.stderr, /PROBE_BASE/);
  assert.doesNotMatch(result.stderr, /Executable doesn't exist/);
});
```

Correct ordering → `resolveBase` throws first and stderr names `PROBE_BASE`. Broken ordering →
`chromium.launch()` reaches a browser path that does not exist, and stderr carries playwright's
error instead. **No timing threshold** was introduced — the task forbade one (F-1084-1 already
complains about load-sensitive suites) and none appears in the diff.

## Findings

**F-1092-1 (non-blocking, observation, no corrective needed).** The `assert.doesNotMatch` half of
the new test is **belt-and-braces rather than load-bearing**: under the mutation the *positive*
`assert.match(/PROBE_BASE/)` fails first, so the negative assertion is never reached. It is not
dead — it would catch a hypothetical future where a launch failure *also* mentions `PROBE_BASE` —
and the master explicitly asked for both directions on the grounds that one-sided assertions are
how rf-29's guard went blind. Recording it so no later reader mistakes the two-sided assertion for
two independent detectors. **No task spawned.**
