## What it does

`scripts/lane-usable.mjs` prints a reassurance when a lane is behind main but none of the
drift is run-surface: *"The gap is bookkeeping only — nothing here can stop a task running."*
`RUN_SURFACE` (`:135-138`) excludes `tasks/` **by design** — ledger rows cannot change whether
code runs. But a master's READ-FIRST cites the ledger **by content** (F-1310-1), so when the
lane's `tasks/` tree is stale, that grep fails **in the lane** and the task stops. The
reassurance was therefore true about the *code* and false about the *dispatch*.

The slice adds `ledgerDrift(branch)` (a `tasks/`-scoped sibling of `surfaceDrift`, same
`branch..main` direction) and splits the empty-surface-drift branch in two:

- ledger also clean → the old sentence, **verbatim and unchanged**;
- ledger dirty → the byte-identical-run-surface half is kept, the *"nothing here can stop a
  task running"* half is **dropped**, and the differing `tasks/` paths are listed (first 8 +
  an `… and N more` tail) under an explicit warning naming the READ-FIRST-by-content failure.

This is a **narrowing**, not a replacement. Both arms are asserted.

## Findings

**F-1424-1 (🟢 non-blocking, no corrective owed).** `ledgerDrift` scopes to the whole `tasks/`
tree, so it counts `tasks/queue/**`, `tasks/done/**` and `tasks/runs/**` churn alongside the
ledger files a READ-FIRST actually cites (`tasks/BACKLOG.md`, `tasks/goals.json`, master
files). In a busy factory the count will usually read high for reasons that cannot break any
grep. That is the **safe** direction — it over-warns rather than under-reassures, which is the
whole point of the narrowing — and the printed path list lets the reader see instantly which
kind they are looking at. Filed so a future fire tightening the scope knows the breadth was
observed and accepted, not overlooked.
