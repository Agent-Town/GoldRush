## What it does

`PicnicHoldSystem.isEnabled()` used to ask a question the contract never meant to answer: it counted
`heroStart` stake markers and returned true at `>= 2`. Exactly two shipped contracts satisfy that
predicate — the intended `e6-picnic` (not admitted) and **`e10-last-claim`, which IS admitted**. So a
shipped contract silently acquired the picnic quarter-of-enemies stake-pressure targeting *and* the
picnic loss condition (`onAllClaimed -> postHeroDeath`). That is why b4v3 was merged at `ccf8dc57d`
and reverted the same fire at `75125b4da`.

This slice re-lands the whole b4v3 stack and replaces the coincidence with a **declaration**:

```ts
static isEnabled(contract: Pick<ContractManifest, 'twist'>): boolean {
  return contract.twist.picnicHold === true;
}
```

`twist.picnicHold: true` is declared by `e6-picnic` alone (`assets/contracts/epoch-6-atomic/contracts.json:486`).
Both engines' construction sites now pass the contract rather than a marker array — `Game.ts:807`
(`this.activeContract`), `HeadlessContractSim.ts:719` (`this.manifest`), and `MechanicsManifest.ts:654`.
Scope 4 is done too: the final snapshot's `picnicHold` field is now `this.picnicHold.active ? … : null`,
matching its `crawler`/`deepwater`/`atomic` neighbours, so no admitted contract's determinism hash
grows a field.

**Where the player sees this, in a plain boot:** nowhere new, and that is the intended outcome.
`e6-picnic` admission stays REFUSED, and `e10-last-claim` is restored to exactly main's behaviour.
The player-facing delta of this merge versus main is **zero by design** — it is a correctness slice
that stops a shipped contract from inheriting another contract's rules.
