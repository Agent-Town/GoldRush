## F-1414-1 — the cause of F-1400-3, verified at source (BLOCKING, cure authored)

The run named a cause. **I did not inherit it; I read the code.** It is correct, and the chain is four links:

1. **The auto-secure gate is keyed on the mere PRESENCE of a baron block.**
   `src/sim/HeadlessContractSim.ts:225-227` *(grafted file — the coordinate does not exist on main)*:
   ```ts
   autoSecureWaveForRun: () => this.manifest.twist.baron && !this.baronBeaten
     ? Number.MAX_SAFE_INTEGER
     : this.manifest.twist.secureWave ?? Balance.run.secureWave,
   ```
   Any contract with a truthy `twist.baron` can never auto-secure until `baronBeaten` flips.

2. **`baronBeaten` flips on exactly one string.** `HeadlessContractSim.ts:392`:
   ```ts
   if (event.type === 'enemy_killed' && event.eliteKind === 'baron') this.postBaronDefeat(event.at);
   ```

3. **Hill Mine's boss is not `'baron'`.** `assets/contracts/epoch-2-steamworks/contracts.json`, `e2-hill-mine`:
   `bossKind: "railcar"`, `secureWave: 12`, `escortCount: 6`, plus a five-part `components` array
   (wheels, boiler, …). Components spawn at `src/systems/WaveSystem.ts:866` with
   `eliteKind: baron.bossKind ?? 'railcar'` — so every spawned part carries `'railcar'`, **never** `'baron'`.

4. **Therefore `baronBeaten` can never become true on this contract**, auto-secure is withheld forever, the
   run sails past `secureWave: 12` and trips the `e45cf7c5` ceiling at wave 15.

**This is the behaviour change F-1400-3 recorded, with its mechanism now named.** It also confirms s1413's
epistemic call verbatim: `e45cf7c5` put a ceiling under the loop, converting a 99.4%-CPU hang into a clean
red. The bound was real and the diagnosis it enabled is exactly why this run could see the cause in 5
minutes. **The symptom was bounded; the cause was untouched.**
