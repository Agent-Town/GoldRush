## What it does
Filing a bug report at the Complaints Desk grants and equips **The Complainant's Coat** on the spot,
in-world (*"The county pays honest eyes."*). A minted **prize stub** typed into the desk redeems
**The Gilded Coat** through a new Cloudflare Pages Function, `functions/api/redeem.ts`. Skins are
profile data (`ProspectorSkin.ts` → localStorage), ride profile export/import via `PROFILE_DATA_KEYS`,
and bind to sprite sheets **by name with stock fallback** — so the grant works today and the art can
land whenever (placeholder-first law). Codes are minted operator-side by `scripts/mint-prize-codes.mjs`
(`npm run mint:prizes`), token-gated.

### F-1079-1 — `vp-02-sprite-animation` 10 red: PRE-EXISTING, not this slice (non-blocking)
`SpriteAnimator.ts` is the blast-radius file here — shared, widely used — so the reds landed on the
prime suspect. They are not ours, and this was **measured, not argued**:

- **Isolated** (single spec, `--workers=1`, desktop only) → **5 failed / 6 passed, 4.1m**. So it is *not*
  the F-1078-2 contention shape; load was ruled out first.
- **Control:** `SpriteAnimator.ts` cp-reverted to main's version, same isolated command →
  **identical 5 failed / 6 passed, identical 4.1m**. The failures survive the removal of the only
  plausible cause.
- **Root cause, newly pinned:** the runtime serves `char-hero-sheet-rotation-**f**-r0c0.png` (the
  **female** hero sheet) while vp-02 still asserts the male-named `char-hero-sheet-rotation-r0c0.png`.
  It is a stale spec trailing the hero-roster migration.
- **Orthogonality:** this slice's sprite code only branches for `assetSlots.charProspectorAgent` at a
  **non-stock** skin. vp-02 exercises `charHero` and sets no skin, so the new code path is never entered.

Consistent with the standing anim-red cluster already recorded in BACKLOG (run-cast-scale-up F-2,
run-gait-stride F-1) with a corrective owed. This fire adds the `-f-` filename as the concrete cause.

### F-1079-2 — `mint()`'s errors escape the handler (major, server-side, operator-facing)
`redeem.ts:33` is `return mint(...)` inside the `try`. In an async function a plain `return` of a promise
resolves **after** the try scope exits, so the `catch` at `:43` never runs. Verified by running it:
`try { return inner() }` → **rejection escapes**; `try { return await inner() }` → caught.
**Failure:** an authenticated mint with 21 codes, a duplicate, or a malformed code returns a Cloudflare
**500 HTML page** instead of the intended `400 bad_payload`; a `kv.put` failure likewise 500s instead of
`503`. Unreachable without `BUG_OFFICE_TOKEN`, so operator-facing only. **Fix:** `return await mint(...)`.

### F-1079-3 — the stub is burned before the client can keep it (major, unrecoverable if it fires)
`redeem.ts:41` does `kv.delete` **then** responds; the client then tries to persist. If the response is
lost in flight, or the owned-list write fails on quota, the player sees *"the clerk stamped the stub, but
this browser could not hold the coat ledger"* — and the code is **permanently dead**, since every retry
returns `bad_stub`. The `canPersistProspectorSkin()` pre-check probes the *selected-skin* key, not the
*owned-list* key that actually fails. No operator recovery short of re-minting.
**Fix:** make redemption idempotent — `kv.put('prize:'+code, 'redeemed:'+ts)` instead of `delete`, and
return `ok:true` for both fresh and already-redeemed stubs. Single-use buys nothing here (see the framing
note below) while costing a real prize.

### F-1079-4 — no rate limit; diverges from every sibling endpoint (major, cost/DoS)
`_bugs.ts:60`, `telemetry.ts:76` and `_accounts.ts:95` all gate public writes with
`bumpCounter(kv, '<ns>:ratelimit:' + await clientIpHash(request))`. `redeem.ts` copies their CORS block
**verbatim but drops the rate limit**, so an unauthenticated caller can issue unbounded POSTs, each a
billed KV read. CORS does not help — it is a browser control, and a non-browser client sending no
`Origin` passes. **Brute-forcing codes is *not* the risk:** `randomBytes(12)` is 96 bits and the
`^GR(?:-[A-F0-9]{6}){4}$` pattern matches it exactly. **Fix:** reuse the `_bugs.ts` helper; 429 on trip.

### F-1079-5 — the coats are currently invisible in play (product, Mistake #10 class)
`prospectorSkinSheetFile` maps to `char-prospector-{gilded,complainant}-sheet-hover8.png`, and **no such
asset exists in the repo**. Both coats therefore fall back to the stock sheet — the slice's own e2e
asserts exactly this (`data-prospector-sheet` = `'stock'`), so it is honest and deliberate. But per

answer is: **they read a congratulation line and their prospector looks identical.** The prize is a

## Framing that should be stated, not fixed
The grant is pure client-side `localStorage`. Any player can own the Gilded Coat with one devtools line.
The endpoint therefore enforces **nothing** — it is a delivery mechanism, not an entitlement system.
That is entirely acceptable for a cosmetic in a single-player browser game, and it is why F-1079-3's
"single-use" property is worth trading away for recoverability. It must not later be treated as an
ownership oracle.

## Checked and clean
- **No secret reaches the client bundle.** `BUG_OFFICE_TOKEN` appears only in `functions/api/_bugs.ts`,
  `functions/api/redeem.ts` and `scripts/mint-prize-codes.mjs` — nothing under `src/`.
- **An unauthenticated caller cannot mint.** The token check precedes payload validation, returns 404
  (not 401), and 404s when the binding is unset — no oracle. The spec asserts this.
- **Input validation is genuinely careful:** `content-type` enforced, both the declared `content-length`
  *and* the real byte length checked against a 2 KB cap, array bounded 1..20, duplicates rejected,
  unknown top-level keys rejected, codes normalized and pattern-matched.
- **Client error handling is defensive:** every storage touch is try/caught, `grantProspectorSkin` rolls
  both keys back on partial failure, the `busy` guard is set before the first `await`, and unreachable /
  non-JSON responses land in the `offline` / `declined` branches.
- **Known and accepted:** get-then-delete is not atomic under KV eventual consistency — already named in
  an in-code comment with the Durable Object fix.
