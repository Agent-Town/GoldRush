## Findings

- **F-ASSAY-E2E-1 — CURED.** `scripts/gr-sim.mjs:257` hardcoded `version: 1` and wrote no `runStart`, while `assay-worker.mjs:81` and `assay-replay.mjs:24` refuse anything but v2. The door now writes `RUN_TAPE_VERSION` and copies `HeadlessContractSim.runStart`, a read-only field captured in that constructor from the meta `RunManager` just installed plus the research state read at its top — the tape contract's §3 "recorded, never re-derived". Proven on both branches: a virgin boot reads `{territory:0,science:0,hero:0,agent:0}` with `taken:[]` (exactly `RunTapeRecorder`'s own default), and a storage-injected boot reads its own `{territory:2,science:1,hero:0,agent:3}`. Nothing in the sim consumes it; the floor is byte-unmoved.
- **F-ASSAY-E2E-2 — CURED, on the side that was wrong.** An accepted `SECURE_CHOICE` at the boundary is stamped `round(timeAlive * 30)`, which equals the elapsed tick count exactly, and both validators cap an entry at `durationTicks - 1` → HTTP 400 `bad_payload`; only silence could be submitted. The recorded tick is the truth (that order is what secured the claim; moving it earlier would replay into a closed secure window), so the tape's declared duration is what moved: `durationTicks = max(elapsedTicks, lastEntryTick + 1)`. **No validator was loosened** — the probe's refused exhibit `tape-secure-verb-REFUSED.json` is still refused by both `validateTape` and `validateRunTape`, while the newly written boundary tape is accepted by both and verifies.
- **F-ASSAY-E2E-3 — MECHANISM PINNED, CURED BY ROUTING.** The version stamp was not enough: the probe's v2 control replayed in the browser to `fnv1a32:09843b86` / unsecured / 0 waves / 23.9 s against a recorded `fnv1a32:a4d0de7f` / secured / 10 waves / 300 s, reproduced here before any change. Cause: the two engines disagree about the world at tick 0, before any order — `the-claim`/`e1-the-claim-01` shows three live seams in gr-sim (`seam-2 @anchor1 (-9,6.7)`, `seam-3 @anchor3 (7.5,6.5)`) against two in the browser (`seam-2 @anchor5 (25,6.9)`, `seam-3 dark`). `agentOrdersEventLogHash` hashes the ACCEPTED submission stream and acceptance is world-dependent, so a different world is a different hash by construction. `scripts/assay-replay.mjs` now routes on the reel's own content — `agent_orders` entries mean `HeadlessContractSim`, everything else keeps the browser path byte-unchanged — using the same discriminator the browser replay seam already computes (`Game.ts:6892`). **Parity: the probe's own run replays to `fnv1a32:a4d0de7f` with `secured/10/200/300` in 6.3 s.**
- **F-ASSAY-E2E-4 — CURED.** No read surface emitted `assayReason`. `GET /api/standings?epoch=&contract=&verdict=<reel id>` now serves assay state, time, replayed hash and (for a rejection) the reason, keyed on the tape id exactly as `?reel=` is. No ranking surface changed.
- **F-ASSAY-E2E-5 — CURED in the same pass (found reviewing my own diff).** Serving `assayReason` turned a private operator string public, and an instrument failure carries the box's absolute paths through `error.message`. The POSTed reason now reduces absolute paths to their basename while the worker's JSONL log keeps the whole message; every meaningful reason passes through byte-unchanged (tested both directions).
- **F-ASSAY-E2E-6 — OPEN, owner's desk. The browser cannot replay a standing-order tape at all**, and this bites a BROWSER recording made by a human riding with standing orders, not just a door reel. Two independent defects, both measured: (a) the solo upgrade-draft clock is WALL-CLOCK (`Game.ts:9158`, `performance.now() + Balance.offers.pickSeconds`) while `levelup` freezes the sim clock, so a compressed headless replay — 300 sim-seconds in ~6 wall-seconds — never expires the draft and the run stalls forever (measured: frozen at `timeAlive 23.87`, playing its remaining ~8,000 ticks against a stopped clock); (b) `tickStandingOrders` runs only inside the `simActive` branch (`Game.ts:2773` → `:2960`) and `simActive` is false in `levelup` (`GameState.ts:22`), so a recorded `PICK_UPGRADE` can never execute even if the draft did expire. Neither is touched here. **Recommendation:** one slice, sim-clock the draft deadline (it is already sim-clocked in `HeadlessContractSim.syncUpgradeOfferClock`) and tick the executor while a draft is open, gated by a browser agent-tape roundtrip.
- **F-ASSAY-E2E-7 — NON-BLOCKING, recorded.** `gr-sim` writes `difficulty: <preset>` into the tape but only calls `applyDifficultyPreset` when a preset was named on the command line. The default Balance is byte-identical to `trail` (measured: all eight mutated fields equal before and after), so nothing is wrong today — but the tape asserts a preset the process may not have installed. The new agent replay installs the declared preset unconditionally, which is the safe side; the door should do the same the day the defaults and `trail` part company.
