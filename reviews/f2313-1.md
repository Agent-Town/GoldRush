## What it does

`scripts/run-guards.mjs` assembled a per-leg row on every gate run (`{guard, rc, seconds, output}`)
and discarded it microseconds later; `grep -c "writeFileSync\|appendFileSync"` over the pre-change
file returns **0**. This slice appends one **projected** record per leg to a JSONL after the loop:

```json
{"runId":"2026-08-25T13:35:13.159Z","ts":"2026-08-25T13:35:13.159Z","head":"475a17ed0","roster":"--only","guard":"test:citations","rc":0,"seconds":1,"p95":null}
```

Four properties carry the design, and each is load-bearing rather than stylistic:

1. **The record is a PROJECTION, never `rows`.** `rows` carries `output` — the entire stdout+stderr
   of each leg, one of which is `test:node-guards`, a ~530 s battery of 503 tests. The literal
   reading of F-2312-1 (b) would have written that transcript into a **tracked** file on every gate
   run. The projection drops `output` and the guard asserts its absence.
2. **The path is anchored to `import.meta.url`, not `process.cwd()`** — the F-2220-1 / F-2221-1
   defect class. Deliberately NOT a git-resolved *main* root: by F-2225-1's discriminator this
   tool's question is self-scoped ("what did the gates in THIS tree measure?"), so a lane's own
   timings are correctly the lane's. `GR_GUARD_STATS_PATH` overrides.
3. **Fail-soft, exit-invariant.** The append is try/caught and `process.exit(failed.length ? 1 : 0)`
   is untouched. An instrument that can red the factory by its own failure is worse than no
   instrument; this one cannot.
4. **Declares on stdout on BOTH paths** (F-2208-1) — a success line naming path + record count, a
   `⚠️` line naming path + error. A declaration that appears only on failure re-creates the
   ambiguity it removes.

The p95 at the parse site was previously captured into a loop-local and used only for display; it
now reaches the record. `head` falls back to the **string** `'unknown'` (F-2212-1: a careless
truthiness test at a future call site falls toward noticing).

## Findings

**F-2314-1 — NON-BLOCKING, and recorded as a NEGATIVE RESULT with its mechanism (F-2214-1's rule),
so the next fire inherits a reason rather than re-deriving it.** I checked whether an empty `rows`
could append a blank line to the tracked JSONL — `records.map(...).join('\n')` over an empty array
yields `''`, and the code appends `'\n'` regardless, which would write a stray empty line that the
guard's own `records()` reader (`trim().split('\n').map(JSON.parse)`) would throw on. **It is
UNREACHABLE, on all three selection paths, by construction:**

- `--only`: an unknown name *or* an empty request exits **2 before the loop** (the file's own
  comment explains why: "silently narrowing to nothing would report a green over zero guards").
  Survivors are all in `GUARDS`, so `selected.length >= 1`.
- `--changed-since`: `wanted` is seeded `new Set(GATE_GUARDS)`, and `GATE_GUARDS` is a 5-entry
  literal — non-empty unconditionally.
- default: `selected = GUARDS`, non-empty.

No cure is proposed and none should be built: a guard for an unreachable branch is decoration, and
by s2226's duty a manufactured defect that reddens nothing is a branch no test can reach.

**F-2314-2 — NON-BLOCKING, priced so it is not mistaken for a problem.** `logs/guard-stats.jsonl`
is **not** gitignored (`git check-ignore` rc=1), so after the first real gate run it appears as
`?? logs/guard-stats.jsonl` until someone adds it. That is the master's stated intent, and it is
aligned with the RETENTION LAW (compaction of tracked files is lawful; deletion of untracked
history is not). **Growth is negligible and here is the number so nobody has to guess:** the full
roster is 12 legs at ~160 B per record ≈ **1.9 KB per full gate run**. This is a datum for the
owner's live F-1103-2 / F-1055-2 retention-pricing thread, **not** a new desk item.
