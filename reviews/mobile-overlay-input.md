## What it does
Fixes full-viewport town overlays that were capturing pointer/touch events across the whole screen, blocking world interaction on mobile (owner's playtest complaint). `src/town/town.css`:
- `.town-ui` era-backdrop wrapper (two sites): `pointer-events: auto` → **`none`** — the translucent full-screen backdrop no longer eats input.
- The name-card *content* gains `pointer-events: auto` — so the actual interactive card still receives input while the surrounding backdrop passes through to the canvas.

Plus a regression harness so this cannot silently come back:
- `e2e/helpers/mobile-overlay-probe.ts` (new): walks all fixed/absolute elements, flags any that cover >20% of the viewport AND fill it edge-to-edge while capturing input, unless they're the one allowed modal.
- `e2e/mobile-overlay-input.spec.ts` (new): asserts the world stays interactive behind the town name-card (canvas receives a pointerdown), and that run overlays (build menu, level-up, death, claim ledger) only own the viewport while their own modal is open.
