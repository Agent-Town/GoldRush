## What it does

`scripts/run-guards.mjs` appends a per-leg telemetry row to `logs/guard-stats.jsonl` at the end of every guard-runner
invocation. F-2315-1 measured that if that file is ever `git add`ed — which the shipping commit's own headline
(`29c674b02`, *"persist … to a **tracked** JSONL"*) promises and s2314's handoff invited — the append turns a clean tree
into a dirty one, breaking the invariant `.claude/skills/drain/SKILL.md:46` asserts as verified and that
`run-guards.mjs:260` already enforces on every child it spawns via `GR_GUARD_NO_ARTIFACT`.

The cure classifies `statsPath` before appending, using `git ls-files --error-unmatch` through `spawnSync` (which reports
by return value and never throws), and reads the **exit code as the verdict**:

| git status | meaning | behaviour |
|---|---|---|
| `1` | untracked, inside a repo | **append** — byte-identical to pre-cure |
| `128` + *"not a git repository"* | outside any repo (the ordinary fixture case) | **append** |
| `0` | tracked | **SKIP + declare** on stdout |
| anything else (incl. other `128`) | could not classify | **SKIP + declare** — fails closed |

The runner's exit expression `process.exit(failed.length ? 1 : 0)` is untouched, so the instrument can never red the
factory by its own bookkeeping.

## Findings

### F-2316-1 — the lane runner's auto-commit sweeps untracked factory logs, because its exclude list is hand-enumerated (NON-BLOCKING for this slice; filed against the runner)

`lane-runner-v3.sh:488` commits lane output with:

```
git add -A -- . ':(exclude).wrangler' ':(exclude)logs/factory-usage.json' ':(exclude)logs/usage-history.jsonl'
```

— an `add -A` over the whole worktree minus a **hardcoded list of exactly three paths**, two of which are already
`logs/` churn files. `logs/guard-stats.jsonl` was born at `29c674b02` (s2314) and was never added to that list, so the
runner swept it into `f86d3412c` — **13 rows of its own gate telemetry.**

**Codex did not violate the firewall.** Its report states *"No commit created"* and its final live proof shows
`?? logs/guard-stats.jsonl`, untracked. The commit is the runner's, and the master's NO list
(*"do NOT `git add` it — tracking it is a separate decision that belongs to the finding, not to you"*) plus s2315's
standing `🚫 BINDING` both bind the implementer, not the shell script that commits on its behalf. This is a
**firewall success wearing a violation's clothes** — the discipline held everywhere a human wrote it and failed in the
one place nobody had written it down.

⚠️ **The interaction is what makes this worth a finding, and it is the reason the file was excluded rather than waved
through.** Once this cure is on main, tracking `logs/guard-stats.jsonl` no longer dirties the tree — it **silently
disables the feature**: the runner classifies the path as tracked, skips the append, and prints one line. The stats file
would freeze at whatever rows it was committed with, forever, while every gate reports success. So the sweep's
consequence has *changed shape* under the very cure it rode in with: it is no longer a dirty tree, it is a dead
instrument that still says `rc=0`. That is strictly harder to notice, and it is exactly the polarity this streak keeps
finding.

**Severity, stated honestly and not inflated:** the sweep is **live** (it happened, in this slice, today), but nothing
reached main — the exclusion held, and `logs/guard-stats.jsonl` is untracked on main as of `858baeb81`. The class,
however, is general: **any** new untracked `logs/*` file the factory invents is swept by default, because the list
enumerates by hand what git already knows how to answer.

**Recommended cure (not taken here — it is runner surface, outside this slice's firewall):** ask the question
structurally rather than by list — exclude `logs/` wholesale at the lane-commit site, or drive the excludes from
`.gitignore` — so a new factory log cannot arm this by simply being born. A hand-maintained list of what git already
knows is a defect awaiting the next filename.
