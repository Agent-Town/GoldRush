Both are a design question for the owner, not a balance edit for an agent: *should the trestle and incline claims run a pressure line, or is their railcar meant to fall to turrets alone?*

**Findings**
- **F-E2PA-1 — the tape cannot declare the medal.** `specs/agent-play/tape-contract.md:11` fixes `runStart` as `{meta, research}` and says medals are excluded because "no currently-assayable contract's sim reads them headless; extend `runStart` the day one does, with a version bump." This slice is that day: `sky_rocket_battery` re-checks `hasBaronMedal()` at fire time. Storage injection (the campaign-harness path) carries it; a tape-v2 replay would not. **Owner/attended: `runStart` v3 with a medal track.**
- **F-E2PA-2 — `Terrain` is a module-level singleton keyed to `?contract=`.** `Terrain.ts:78` reads `activeContract()` at module load, so a harness that omits the parameter silently runs every contract on the DEFAULT claim's terrain. Measured: a hero clamped to z ≤ 31.5 on a size-96 map, putting all three coal seams (z 39–43) permanently out of bounds. Every measurement in this slice was re-taken after the fix. A one-line guard in `HeadlessContractSim`'s constructor — refuse to boot when `activeContract().id !== boot.contractId` — would have made it impossible.
- **F-E2PA-3 — two browser couplings are still unmirrored, both named.** `Game.ts:2618` multiplies turret fire rate by `pressureArsenalSystem.turretFireRateMult` (gated on `boiler_battery`) and `:2620` spends 2 pressure/second on auto-pan while channelling (gated on the `auto_pan` upgrade stack). This sim calls neither, and its `applyProgressionStats` already applies `stats.panTickMult` unconditionally — so a headless run that picks `auto_pan` gets the pan bonus WITHOUT the pressure the browser charges for it. Pre-existing and small, but it flatters headless; it belongs in the same slice as `continuedStudyBonuses`, which the sim also ignores (that one penalises headless).
- **F-E2PA-4 — nearest-first targeting makes a stationary hero blind to a boss.** `TargetingSystem.findNearest:57` has no boss priority, and the headless hero never moves (`IDLE_INTENTS`). Measured on the wrong-terrain runs: 3,451/3,451 railcar HP still standing after a full wave-12 pass while ~30 trash enemies stood on the stake. The cure that worked is a site plan, not a code change — guns placed away from the stake and near the rail have no trash in range — and it is now written into the prover as its `BATTERY` table. A browser player solves this by walking; a rider cannot.
- **F-E2PA-5 — `View.ts:458` runs `tier` through `integer()`, which yields NaN when the field is absent**, so the idiomatic `entry.tier ?? 1` default silently drops every building. Cost one wrong conclusion here before it was caught.
