## What it does

Before this slice the Run Ledger only printed a **Meta earned** row when a run ended with
`reason === 'secured'`. A player who secured a claim, chose **Stay for the Rush**, and then
died had genuinely banked the payout — but their ledger card silently dropped it. The run
read as if it had earned nothing.

The slice replaces that outcome-shaped test with the claim the row actually makes:

```ts
...(this.paidRunId === this.runId && this.lastPayout ? { metaEarned: { ...this.lastPayout } } : {}),
```

Separately, `trackLabel` moved from a private function at the bottom of `RunManager.ts` into
`MetaProgress.ts`, so the Claim Office payout list and the Run Ledger row share one authority
for track capitalisation instead of `RunLedger.ts` hand-rolling `track[0].toUpperCase()`.

## F-1192-1 — the two predicates ARE distinguishable, and now one test says so

**s1191 stated that the exact predicate and the proxy are "INDISTINGUISHABLE by any test the
current three-value type permits," so the preference was structural only. That is half right,
and the wrong half was load-bearing.**

`applySuspendRunState` assigns `stayedForRushRunId` from `state.rush` (`:160`) and `lastPayout`
from `state.payout` (`:166`) **independently of `state.secured`**, while `paidRunId` comes from
`state.secured` alone (`:161`). So the suspend shape `{secured:false, rush:true, payout:{…}}` is
representable — a run that claims a rush and carries a payout blob it never banked. It reaches
`endRun('rush')` via `:92`. Under that input:

| Predicate | Result |
|---|---|
| **(A) `paidRunId === runId && lastPayout`** — SHIPPED | withholds `metaEarned` ✓ correct |
| **(B) `reason !== 'death' && lastPayout`** — the proxy | **emits a payout the player never earned** ✗ |

**Measured, not argued** — by mutating the *subject* and re-running:

| Tree | `e2e/m3-05d-unpaid-rush-guard.spec.ts` | slice's own 14 tests |
|---|---|---|
| shipped (A) | **PASS** (`outcome=rush metaEarned=undefined`) | 14/14 |
| mutated to (B) | **FAIL** at the `metaEarned` assertion | **14/14 — still green** |

So s1191 was right that the **existing** suite cannot discriminate, and wrong that **no** test
can. No new `RunEndReason` and no fake test were needed — only an input the existing type
already permits. The shipped predicate is therefore not merely tidier; it is **safer against an
untrusted suspend/import payload**, and that safety is now guarded rather than asserted.

**Disposition (non-blocking, shipped code is correct):** the guard was added drain-side as
`e2e/m3-05d-unpaid-rush-guard.spec.ts` in its **own commit**, separate from the runner's merge,
so attribution stays honest and one revert removes it. Owner veto window applies.
