# reviews/081 — Continue button regression for suspended runs

- **Slice/branch/tip:** 081-continue-button-regression · MAIN slot · fix commit `1d30cc83` (on `main`, base `d0e4e3dc`).
- **Verdict:** MERGED. Gate green; the one adjacent red is a proven pre-existing stale test, orthogonal to the hunk.

## What it does
The resources economy (Session-B merges) made `economy.resources` REQUIRED in the suspend decoder: `decodeResources(undefined)` fails `isRecord` → pushes `economy.resources must be an object` → returns `null` → the economy decode returns `null` (`RunSuspend.ts:898`) → the whole suspend read returns `null` → the start menu's `suspend` is falsy → the `start-menu-continue` button never renders. So every suspend slot written before the resources field existed (and the 044 fixture, which omits it) silently lost its Continue button.

The fix adds `migrateLegacySuspendResources(storage)`, called at the top of `StartMenu` render (before `readRunSuspend`): it reads the stored suspend, and if `economy` exists but `economy.resources === undefined`, backfills `economy.resources = {}` and writes it back. The decoder then accepts the slot, Continue renders, and clicking it enters the run path. Firewall respected — StartMenu.ts only; `main.ts` untouched; no reintroduction of the dead `onNewClaim` wiring.
