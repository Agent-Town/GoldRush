## What it does

The rehearsal rig used to guess which server it was measuring. Three files each declared their own
hardcoded fallback — `rehearsal/lib.mjs:9` (`REHEARSAL_BASE ?? http://127.0.0.1:5231`),
`rehearsal/segments/e1-depth-play.mjs:27` and `e1-depth-rivercamp.mjs:30`
(`E1_BASE ?? http://127.0.0.1:5247`) — so if any other checkout happened to be serving that port,
the rig would happily drive it and attribute a stranger's code to this branch. That is exactly how
s1077 produced a false P0.

This slice replaces all three declarations with one resolver, `rehearsal/base-url.mjs`, that **fails
closed**: it throws unless the env var is set *and* an `lsof` pid→cwd probe proves the listener was
started from this checkout. The defaults are **deleted**, not relocated. `lib.mjs`'s HMR console
filter — previously the literal string `ws://127.0.0.1:5231` — is now **derived from the resolved
base**, so it cannot go vacuous when the port changes and start counting HMR noise as real page
errors.

`export const BASE` was removed from `lib.mjs`; resolution in `lib.mjs` is **lazy** (inside
`openSegment`, before the browser launches), so importing the module is still side-effect-free for
the 20 segments that depend on it. The two `e1-depth-*` drivers resolve eagerly at module top level,
which is right for standalone drivers: they fail before Playwright starts.

**Scope: 6 files, +94 / −9.** Zero `src/` change, zero `e2e/` change, no playwright run.

## Findings

### 🟠 F-1089-1 — the new guard would NOT catch the defect it was written to prevent

**Non-blocking. The cure is correct; the *net* has a hole.**

The master mandated fail-closed on four branches (unset · foreign cwd · no listener · `lsof`
unusable). The resolver honours all four — I measured that above. But the automated guard covers
only **happy-path · foreign · no-listener · unusable-probe**. **There is no test for the UNSET
branch**, and the unset branch is precisely where the original defect lived (`?? 'http://127.0.0.1:5231'`).

**Proved by mutation control, not inferred.** I restored the exact defect — reintroduced the
hardcoded `5231` default and disabled the unset branch — and re-ran the guard:

```
MUTATION APPLIED: hardcoded 5231 default restored, unset-branch dead
ℹ tests 4 · ℹ pass 4 · ℹ fail 0
>>> GUARD STAYED GREEN WHILE THE ORIGINAL DEFECT WAS RESTORED <<<
```

Reverted; `rehearsal/base-url.mjs` verified byte-identical to the lane tip (`7cde854c`) and
`git diff -- rehearsal scripts` empty. Every test sets its own env var, so none of them can ever
observe a default being reintroduced.

➡️ **Corrective authored as rf-28 for lane-a** (`tasks/lane-rehearsal-unset-guard.md`): add the
missing unset-branch assertion, with a mutation control proving it reddens when a default returns.

### 🟢 F-1089-2 — the real `lsof` path is covered by no automated test (recorded, not fixed)

`probeListener` is only ever reached through the DI default; every shipped assertion injects a stub.
Its `lsof` output parsing (LISTEN-row pid extraction, `-Fn` cwd line) is therefore exercised only by
hand — by the runner's truth table and by mine. This is a reasonable trade (an automated test would
have to bind a real port), but it means a future refactor of the parsing could pass the suite and
still be wrong. Bundle with F-1089-1 if attended wants a port-binding integration test.

### 🟢 F-1089-3 — residual named by the runner, confirmed by me

`scripts/probe-plain-boot-console.mjs` defaults to port **5188** and opens a browser without any
ownership check — the same class this slice just cured, in a script outside the master's firewall.
The runner reported this honestly rather than fixing it out of scope (correct per §4.5). Candidate
for the next rung of this ladder.
