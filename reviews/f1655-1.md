## VERDICT: MERGED — the cure works on the real subject, and the defect was reproduced as a control

## What it does

`scripts/suite-red-inventory.mjs` reduces a Playwright raw JSON run into `logs/suite-red-inventory.md`.
Until this slice it built its output fresh and wrote it, so every legitimate refresh **erased the
ten hand-authored sections** the factory had appended to that report across ~14 fires — 291 of its
844 lines, including `## Corrections since the snapshot`, which `scripts/red-inventory-lookup.mjs`
parses by its exact header and which states the very doctrine ("the snapshot is NOT rewritten…
that would launder a real drift") the reducer was violating.

The cure reads any existing output, splits it on `## ` headings, classifies each section as
**generated** (its heading is one the current run emits — derived from the code under test, so
there is no second list to drift) or **preserved**, and reassembles: preserved sections that sat
before `## Failing tests` are re-anchored there, the rest go after the generated body. A loss
guard then counts every preserved section's exact text in the assembled result and **throws before
writing** if any would be lost — fails closed, output untouched.

## Findings

### F-1656-1 (NON-BLOCKING, factory-ops, cured this fire) — the runner finished the work and then lost it

The run completed `READY-FOR-GATES` with correct output, but the lane branch read `ahead=0` and
`lane-usable.mjs` reported the two files as **tracked dirt**. The run log's final lines show why:
the runner's auto-commit `git add` was rejected —

```
The following paths are ignored by one of your .gitignore files:
.wrangler
hint: Use -f if you really want to add them.
```

— so the add aborted, the commit never happened, and 110 lines of gated-quality work sat as
staged-but-uncommitted content in a lane the next refill would `reset --hard`. **This is the
Reset Massacre precondition arriving by a new route** (w1-03 / polish-02, Mistake #2): the lane
looks empty to every ahead/behind probe while actually holding undrained work, so the standard
"is this lane safe to refill?" question answers *yes* and is wrong.

It was recoverable here only because `lane-usable.mjs` reports **tracked dirt separately from
untracked debris** (F-1299 lineage) and a fire read the word rather than the exit code. The
content was committed unchanged as `b9f49748e` and drained normally.

**Owed:** the runner's commit step should not let an ignored path abort the add of legitimate
TOUCH-ONLY files. Not fixed here — it is `scripts/lane-runner-v3.sh`, outside this slice's
firewall, and the dispatch site is the coordinate §4.10b warns rots on every edit. Recorded in
BACKLOG for a dedicated corrective.

### F-1656-2 (NON-BLOCKING, latent, no action taken) — two edges the contract does not cover

Both are properties of the ruled contract rather than defects against it, recorded so a later
editor does not rediscover them as surprises:

1. **Content above the first `## ` heading is still replaced.** The reducer's preservation is
   section-scoped, so a hand-authored line written into the preamble (lines 1–16) would be
   silently dropped, and the loss guard — which only counts `preservedSections` — would not see
   it. Verified **not live**: lines 1–16 of the current report are byte-for-byte generator output.
2. **`failingIndex` is unguarded.** Assembly anchors on `generated.indexOf('## Failing tests')`;
   if that heading ever stopped being emitted the index would be `-1` and the slices would
   mangle the output. Verified **not live**: it is an unconditional string element at
   `scripts/suite-red-inventory.mjs:277`, not inside a branch.

Neither blocks. Both would be cheap to close if this file is edited again.
