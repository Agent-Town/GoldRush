3. **Chromium for the assayer.** With the worker no longer root, `chromiumSandbox: true` becomes possible in `scripts/assay-replay.mjs` (playwright's default is off under root); flip it only after the worker runs green as `goldrush` for one replay.

5. **The verify rate limit.** The mirror already carries `limit_req_zone $binary_remote_addr zone=verify_guesses:10m rate=10r/m;` at the top level and `location = /api/verify { limit_req zone=verify_guesses burst=5 nodelay; limit_req_status 429; … }`; apply as in the mirror.
6. **Apply and prove.** `nginx -t`, `systemctl daemon-reload`, restart the four units, then: `systemctl status` all green; one sign-in code requested and verified from a phone; one reel assayed (`journalctl -u goldrush-assay -n 50` shows a verdict); the ledger backup timer fires (`systemctl list-timers`); `curl -I https://agenttown.app/api/verify` from a second machine twelve times in a minute returns 429 on the last ones.

## One variable that never goes to Pages (localhost-cors-2, 2026-09-26)
`ALLOW_LOCALHOST_ORIGINS` is the development switch that lets a page on `http://localhost` or `http://127.0.0.1` past every door's CORS check (`functions/api/_cors.ts`). It belongs only in a developer's gitignored `.dev.vars` (copy `.dev.vars.example`), which `wrangler pages dev` reads, and in the test harnesses that start the functions themselves. Never set it on the Pages project, production or preview (no `wrangler pages secret put`, no dashboard variable, no `[vars]` entry in `wrangler.toml`), and never in `/etc/goldrush-ledger.env` (the ledger forwards an explicit key list without it, `server/ledger/serve.mjs`): unset, every door refuses a localhost origin, which is the production default. The variable-names read that measured F-SF1-8 is the check: this name must never appear in either environment's list. After this lands, a game served locally (the vite dev server) that talks to the live county is refused by every door; that is intended (F-LC2-5).
