**Verdict: banks fails on both trees, so it is not a regression since `d30d50451` and not `ux-entry-robustness-1`; nor is it an older game regression. It is the instrument (F-MPP1-1).** The mechanism, read in the code:

1. The game banks a secured score AT THE SECURE TICK. The `run_secured` handler (`src/game/Game.ts:1965`) calls `recordRunScore(..., true, ...)`, which writes the row through `recordScore`. That is the design of `07248387a` (2026-07-22, "feat: lock Claim wins at wave ten": "Banks the score and telemetry at secure, preserves it through Rush suspend/death"), the overlay tells the player so ("The win is banked."), and `e2e/locked-win.spec.ts` asserts it, green on both trees (A2, B2).
2. The Return to Town click (`bank-secured-claim`, `src/game/RunManager.ts:441`) is in-page: `endSecuredRun` awards, ends and resets the run, with no navigation and no URL read before the spec reads the scores. Its `run_ended` handler (`Game.ts:2032`) calls `recordRunScore` again with the SAME `at` (`securedScoreAt`, set at the secure tick), and `recordScore` (`src/game/Scoreboard.ts:53`) replaces the row carrying that `at` in place. The sim is paused between the two writes, so the row comes back byte-identical.
3. The spec takes its `before` snapshot once the overlay is already up (`e2e/playability-secure.spec.ts:833`) and asks for a row the click wrote (`:837`). There never is one, on any map, on any tree since 2026-07-22.
4. `ux-entry-robustness-1` does not touch that path: the `src/` diff `d30d50451..cb484e124` (`main.ts`, `BootGuard.ts`, `InputController.ts`, `ProfileManager.ts`, `ProfileStorage.ts` (a display-name constant), `ComplaintDesk.ts`, `DeathOverlay.ts`, and `Game.ts` hunks for the pick clock) has no line in `recordRunScore`, the `run_secured` or `run_ended` handlers, `Scoreboard.ts` or `RunManager.ts`.

Why it hid: on 2026-09-18 the spec's author saw this exact "0 new rows" on the Dry Gulch and traced it to a second, real cause (the seed's `waves: 30` row trimmed the genuine wave-20 row away), cured that in the seed, and never saw another secured run afterwards (`secure-rows-drygulch-3x2.jsonl`: 0 of 6 secured), so the first cause was never exercised. The banks cell has never passed genuinely on any map or tree.
