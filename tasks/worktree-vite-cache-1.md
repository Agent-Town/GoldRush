## Why (F-TT2-2 and canyon-works-traversal-1's boot failure, both 2026-09-25, both measured)
Every scratch worktree and every lane worktree points its `node_modules` at the primary checkout's, so vite's dependency cache (`node_modules/.vite`, 896 KB today) is ONE directory shared by every dev server on this Mac. Two consequences, both seen today by two implementers: a dev server in one worktree re-optimises the shared cache while another worktree's browser is mid-load (a failed dynamic import, a boot that never happens), and vite's dependency scan resolves `../tsconfig.json` from the real path of the shared modules and reports `[TSCONFIG_ERROR]`, skipping pre-bundling (deps are then found at runtime and the server reloads under the test). The attended toolkit already works around it with a warm boot; the implementers each rediscovered it. A cache dir INSIDE each checkout ends the sharing.
