## Why (owner ruling 2026-09-06, verbatim: "my initial idea was to have seasons and change things from season to season to stay fair to the participants, we are now in the early release phase, we can act freely")
Since era 5 the boards are meant to carry only standings that replay. A contract whose composition changes after riders verified rows on it (Moth Season's grid slice, the E8 physics) leaves rows that were verified under an older engine and would fail today, and nothing can touch them: the door assays only pending rows and keeps a verified row on ties. The owner's long-term design is seasons; in the early release phase he has ruled that we act freely, so the rule now is: re-queue a contract's rows when its composition changes and retire the ones that no longer replay, with a lineage reason, kept in the almanac.

## Scope
1. A `retired` outcome with a reason: the row type gains `assay: 'retired'` (or keeps `assay` and adds `retired: { reason: 'lineage', engineHash, at }`, whichever the existing readers survive; state which and why), never shown on the ranked board, counted in `retiredCount`, still served by the reel WATCH so the almanac can show it. 2. Re-queue on composition change: an authenticated maintenance verb on the door (same secret path the assayer's verdict uses) `POST /api/standings/reassay { epochId, contractId, reason }` that flips every verified row of that contract back to `pending` with a `lineage` marker and rebuilds the assay index; the assayer then replays each under the current engine: match → verified again (same row, new `assayedAt`, same first-secure date); mismatch → `retired` with reason `lineage: recorded under <engineHash>, no longer replays under <current>`. Idempotent; rate-limit exempt for the secret path.
3. The trigger: the droplet's worker (or a small `scripts/assay-lineage-sweep.mjs` run by the deploy after the assayer sync) compares each contract's rows' recorded `engineHash` against the current pin's `cause` text naming that contract; on a match it calls the verb once and logs it.
