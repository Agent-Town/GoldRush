# RUN-RECIPE — the contract-buildables 3D seam (slices 07+)
STATUS: RATIFIED BY LADDER 2026-07-13 (attended; extends RECIPE.md under the same owner order — "all the houses and all other 3D objects that we have in game", 2026-07-13). RECIPE.md governs MODELING; this file governs the RUN-SCENE WIRING that town buildings don't need. Where they conflict, this file wins for run-scene slices.

## Why this file exists
Town buildings mount at FIXED plaza slots behind `?town3dPilot`. Contract buildables (sluice, palisade, turret, stockpile, sentry beacon, boiler house, assay bench, lantern post) are PLAYER-BUILT: dynamic positions, dynamic counts, destroyable, per-run lifetime, and they live in the RUN scene (Game.ts render loop), not TownScene. Without one shared seam, eight tasks would each invent wiring — this file is the seam, written once so the slices parallelize.

## Laws (inherit town laws 1-4, plus)
R1. **Flag**: everything mounts behind `?run3dPilot` (one flag, growing set; `run3dPilot=all` or `run3dPilot=<buildable_id>`). Flag-off boots make ZERO GLB requests — assert it in every spec.
R2. **Sprites are forever**: the existing billboard/sprite render of every buildable remains LITE-tier, load-failure fallback, and the flag-off default. The 3D layer is ADDITIVE and visual-only.
R3. **Read-only sim**: the pilot layer reads buildable instances (id, type, position, alive/stage) from the existing build-state surface (BuildSystem/diagnostics/entity list — READ what exists, add a read-only accessor if none is exposed; never a new write-path). ZERO sim/damage/economy/coordinate changes. One writer per surface stands: BuildSystem owns build state; the pilot only observes.
R4. **Lifecycle**: mount a GLB instance when a buildable appears, unmount+dispose when it dies or the run ends. The module is `src/game/Run3dPilot.ts`, lazy-imported from Game.ts ONLY when the flag is present (boot-bytes budget unchanged — assert vs the perf baseline like mu-02 did).
R5. **Instancing**: many copies of one buildable share ONE loaded GLB (clone scenes or InstancedMesh — modeler's call, but N sluices must not mean N fetches; assert a single network request per model file).
R6. **Markers**: publish `canvas.dataset.run3dPilotState` ('off' | 'loading' | 'ready' | 'lite' | 'failed'), `run3dPilotMeshes`, `run3dPilotTriangles` — mirroring the town markers so the spec grammar clones over.
R7. **Budgets**: buildables are small objects seen many-at-once: target ≤4,000 tris each, hard cap 8,000; ONE ≤512² embedded material each (baked FROM the buildable's existing painted art in assets/processed/ — same bake-from-the-illustration law). p95 frame ≤115% of the sprite baseline WITH 12+ instances built (the spec builds a dense base via the debug seam).
R8. **Spec family**: `e2e/run3d-<id>.spec.ts` per slice, cloned from the first landed one (07 sluice defines the grammar): plain flag-off boot → zero GLB requests + sprites render; `?debug&run3dPilot=all` boot → build N instances via the __GR_TEST__ debug seam (debug-gated is CORRECT here — this is a pilot flag, not a player surface), assert state 'ready', mesh/triangle counts, single fetch per model, destroy one (or let a wave) → assert unmount; `tier=lite` → sprites + zero GLB; invalid-bytes → 'failed' + sprites intact; zero console/page errors; desktop AND mobile-390; p95 ratio recorded to artifacts.
R9. **Scale/origin**: base-center origin, real-world footprint matched to the buildable's existing collision/placement footprint (read it from Balance/build defs — change NOTHING there). Visual height stays inside the sprite's established silhouette band (±15%) so combat readability holds.
R10. **No grounding work** (owner-deferred 2026-07-13) and NO firearms silhouettes on turret/beacon models (ADR-001: frontier-tech — coil/lens/steam forms, never gun barrels; the painted art is the authority).
