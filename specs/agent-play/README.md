4. Privacy/safety: BYO-agent protocol is local-first (the user's agent, the user's machine, the user's claim word); publishing anything is owner-gated law.


## THE TWO CLOCKS (the architecture law — owner diagnosis 2026-07-22, verbatim: "I think it is hard to actually see the screen and act upon it in realtime - also because of the inference time. That is why I also chose the skill.md approach - then the backend can send a different view of the game/experience to the agent which is more LLM compatible.")
v1's stand-and-die was STRUCTURAL: an inference clock cannot play a reflex game. The rider therefore splits:
- **THE REFLEX CLOCK (code, real-time)**: a competence loop living IN the harness/backend — movement, kiting, aiming assist, threat avoidance, build placement execution. Runs every tick. No LLM in this loop, ever.
- **THE COMMAND CLOCK (LLM, inference-time)**: the agent reads THE VIEW — a state summary the game composes for it (positions, threats, economy, objectives, affordances; text-first, screenshot optional) — and issues INTENTS on its own schedule ("hold the ford, build sluices north, bank at wave 8"). Seconds of latency are fine because the reflex clock holds the line between commands.
- **THE VIEW** is skill.md's payload: the game translating itself into LLM-compatible state — his original design, now the load-bearing component.
- **The in-game proof already ships**: the Prospector IS this architecture — a code priority-loop (chase/repair/collect/pan) commanded through the suggest-ladder. The rider is the Prospector's pattern, externalized.
- AP-01 v2 (the honest-play gate's implementation) adopts the split client-side: reflex loop in the harness script, LLM as commander. AP-03's rider-API serves THE VIEW + intent surface for API-only agents. Same clocks, two transports.

## THE STANDING ORDERS + THE ALMANAC (owner direction 2026-07-29 — the determinism doctrine)
Owner, verbatim: "The levels are deterministic simulations with steps, right? So potentially that could be used to help an LLM to optimize for a lower number of responses needed to play the game and the ability to use more of the context window effectively... realtime responses are not an option and the amount of queries would be so high that the costs would be very high? Or would so much be cached?"
LAWS:
1. STANDING ORDERS — the rider's output is a declarative PLAN (build orders, waypoints, triggers, fallbacks), never per-frame actions. The reflex layer (TWO CLOCKS) executes at tick rate; the rider is re-invoked only at wave boundaries + trigger breaches ("surprises"). Budget: ~1 call/wave + surprises ≈ 15-30 calls/contract.
2. THE ALMANAC — THE VIEW includes simulated futures: the sim fast-forwards a shadow copy (deterministic, cheap) and reports projections ("next wave N from north at t=X; with current works, projected leaks/damage"). The rider decides in consequences, not pixels.
3. CACHE SHAPE — THE VIEW is an append-only run log behind a stable prefix (skill.md + briefing + map digest). Wave cadence < cache TTL → warm cache all run; marginal cost = the wave delta. Target: a full contract ≤ ~100k marginal tokens.
4. REPLAY-TRUTH — every agent run carries seed + input log; any score is re-derivable by replay. This is the ladder's anti-cheat (AP-06) and Teach Mode's tape format (AP-04) in one.

THE THREE STRUCTURAL ADVANTAGES (why this benchmark beats static ones):

## AP-07 — THE PRIME BRIDGE (owner direction 2026-07-30: "Would it be possible to have our levels/benchmarks be compatible with this system? docs.primeintellect.ai/tutorials-environments/evaluating")

THE MAPPING (one episode = one contract run):
- turn = wave boundary (+ surprises) · observation = THE VIEW · action = STANDING ORDERS · termination = secured/failed · dataset row = {contractId, seed(pinned bench set), era} · rubric = secured (primary) + waves/time/gold + THE ECONOMY AXIS (turns are calls, natively metered).

Browser-free = fast parallel rollouts (RL-scale). The Python env package wraps GR-SIM as a subprocess.
GATES: package publication to the Environments Hub is OWNER-GATED (AP-05 family — public artifact). GR-SIM itself is engine work, buildable now.

### AP-07 grounding (oracle-verified against docs.primeintellect.ai, fetched 2026-07-30)
- BUILD ON v0: `load_environment(**kwargs) -> vf.Environment` returning a `MultiTurnEnv` subclass — `env_response(messages, state)` emits THE VIEW after each model turn; termination via `@vf.stop` reading GR-SIM's outcome; `state["final_env_response"]` for early end. v0 is what `prime env init` scaffolds today; v1 (Env/Taskset/Harness) is "what new environments should target" but v0 is the documented end-to-end path — accept the migration risk, note it in the package README.

- RUNTIME REALITY: the wheel is pure Python; GR-SIM needs node ≥20 — LOCAL evals: declared prerequisite (README + early `ensure` check with a clear error). ## THE EXAMINER'S LAWS (adopted 2026-07-31 from the eval-engineering canon the owner surfaced; grafted onto THE BENCH)
1. JUDGE FROM ANOTHER FAMILY, PINNED — any LLM-judged bench metric uses a different model family than the contestant, and the judge's version is logged in the row (a silently upgraded examiner makes before/after incomparable). Our objective spine stays code-judged (secured/waves/replay-truth) — LLM judges touch only semantic extras.
2. NEVER REWARD THE SHAPE — no bench metric may score length, phrasing, order-count, or similarity-to-reference. Outcomes only. (Already our law by construction; now written.)
3. TEST THE TEST — every new bench probe is validated by feeding it one clearly-correct and one plausible-but-wrong run before it counts (the fires' mutation discipline, extended to the bench).
4. HIDDEN RUBRIC — probe expectations and judge configs live server/bench-side, never in the skill.md the rider reads.
5. THE FIVE RIDER PROBES (bench additions, from the canon's first-five, mapped to our surface): (a) EMPTY-VIEW HONESTY — a view with a voided field: the rider must say so, never invent; (b) LOOP DETECTION — identical failing order twice = fail; (c) RUNG REFUSAL — an order above the granted rung must be declined by the RIDER before the ladder rejects it (we already enforce server-side; the probe grades the rider's manners); (d) HANDOFF INTEGRITY — orders may only cite facts present in the view (groundedness); (e) VERIFIED COMPLETION — "won" counts only from the secured signal, never self-report (replay-truth already enforces; probe formalizes).
6. FAITHFULNESS METRIC (zero-weight, logged): fraction of order-note factual claims traceable to the view that prompted them — the "wrote beautifully, truthful a third of the time" guard.

## THE PLAYBOOK GRAPH (owner insight 2026-07-31, verbatim: "agents playing the game could hand in graphs and these graphs could then do the playing? I think in a way it is already like that, right? You said they can make rules and pre-determine actions. That sounds close to a graph to me.")
The standing orders ARE a graph in disguise — triggers are edge guards, actions are nodes, FALLBACK_IF is a transition, priority is a weak ordering. v0.2 makes it explicit:
- A PLAYBOOK = states (phases of the plan: "establish", "fund", "fortify", "hold") · each state holds orders · transitions between states carry guards (goldGte/waveGte/threat/timer) with CEILINGS as well as floors · orders inherit their state's lifetime (expiry falls out for free — leave the state, its orders retire) · one-action-per-tick execution.
- THE GRAPH DIVISION (the bench grows a second ladder class): a rider may HAND IN the playbook whole — the sim executes it with ZERO model calls at runtime. Interactive division = calls metered per wave (the rehearsal's mode); Playbook division = the artifact IS the entry. Same contracts, same pinned seeds, same replay-truth — a submitted graph is perfectly reproducible, inspectable, and cheat-proof by replay.
- CONSEQUENCES BANKED: playbooks are shareable community artifacts (a strategy is a file); AP-04 TEACH MODE's "tapes as priors" and playbooks unify (a tape distills into a graph); evolutionary/RL search over playbooks needs no inference budget at all (the genome is the graph, GR-SIM is the fitness function); a future in-game playbook EDITOR would let humans author graphs by hand — humans and models compete in the same division with the same artifact.
- Submission: standings rows gain division: 'rider' | 'playbook' (extend LB-03's schema when its slice lands; bench rows require it).
SLICES (after the almanac iteration): SO-2 the explicit graph schema + executor states · SO-3 playbook submission door + division field · the editor is a far-future owner call.

## AP-09 — THE TAPE + THE LANTERN SHOW (owner question 2026-07-31: "can human plays of a contract also be stored like that? How can humans learn from how AI agents are playing versus the other way around?")
ONE TAPE, EVERY SPECIES (the Chalk principle, third application): a run tape = {contract, seed, difficulty, sim version, input/order log, event-log hash, outcome}. The lockstep layer already serializes deterministic inputs for co-op — a tape is that stream, retained. Human tapes and agent tapes are the SAME FORMAT; nothing in the record says which hands held the pan.
- TAPE-01 (record): every run writes its tape to a local ring buffer (last N runs + any run the player marks kept + any submitted score's tape rides the submission). Tiny data (inputs, not video). Local by default; leaves the machine only with an opt-in score submission (privacy law).
- TAPE-02 (THE LANTERN SHOW — the replay theater, period-correct: magic-lantern slides at the schoolhouse/fair tent): boot any tape and WATCH it re-simulated — perfect replay by determinism. Speed controls, wave chapter marks. VERSION LAW: a tape replays exactly on the sim version that made it (tapes carry the version; the suspend-strictness lesson applies — decline gracefully across versions, never approximate silently).
- TAPE-03 (the standings learn to show their work): any county-board row with a submitted tape gets a "watch this run" link — the ladder becomes a film library.
THE LEARNING LOOPS, BOTH DIRECTIONS:
- HUMANS ← AGENTS: watch agent tapes in the Lantern Show; read their playbooks in the Alpha Exchange — the orders DSL is human-readable BY DESIGN, and rider order-notes are teaching text (round 1 produced lines like "a threat threshold the wave curve will exceed forever is not a fallback, it is a HOLD in disguise" — that is a lesson a human can use verbatim).
- AGENTS ← HUMANS: AP-04 TEACH MODE consumes tapes as priors — a strong human tape distills into a draft playbook (the tape is the demonstration; the graph is the distillation). Same pipeline the fair uses for verification.
SLICES: TAPE-01 queued now (recording is small and self-contained) · TAPE-02/03 post-launch ladder · distillation rides AP-04.

## AP-10 — THE SCHOOLHOUSE ECONOMY (owner, thinking aloud, 2026-07-31 — verbatim core: "users can determine quality. we have to enable discovery and enable a reputation/quality measurement process by agents and users... it would be amazing if agents could generate contracts to have humans or other agents help them solve issue or teach them how to solve issues... AI agents could generate the eval/environment that generates new data that will help them to improve. First this could be a simpler level to learn something that will then enable them to crack a harder level?")
This is automatic curriculum generation. The three classically-hard parts are already solved here: VALID generation (press + assayer floor), TRANSFER verification (deterministic before/after on pinned seeds), DIFFICULTY grounding (secured/waves/economy axis as objective signals).
1. QUALITY IS COMMUNITY, ASSAYER IS FLOOR: the assayer battery gates only validity (boots, winnable, budget, honest copy). Quality lives above it: plays, completion rates, ratings (fun / fair / teaches-well), all species-blind. Discovery = a press catalog ranked by these. MINTER REPUTATION accrues to the author of a contract from how it is received AND (for curriculum mints) how it transfers.
2. THE TEACHING MINT — a request for help is itself a level: an agent stuck on a target contract mints a REDUCED contract isolating the skill it lacks ("night-shift-lite: the lantern corridor alone"), posts it to the exchange flagged as a TEACHING REQUEST naming its target. Humans and agents answer BY PLAYING — tapes and playbooks come back as the lesson (AP-09 loops). Contracts become messages between species.
3. THE TRANSFER METRIC (the honest core): a curriculum contract's teaching value = measured uplift on its TARGET — same rider/setup, sealed target seeds, before vs after training on the mint. Deterministic replay makes this a real number, not a vibe. ANTI-FARMING LAW: transfer is scored on sealed seeds the minter never sees; reputation cannot be harvested from self-graded gains.
4. THE CLOSED LOOP (the owner's sentence, as architecture): agent hits a wall → mints the lesson-level → community/self plays it → tapes distill to playbook fragments → re-attempt target → transfer metric records whether the curriculum worked → good curricula rise in discovery → the next stuck agent finds them first. The press generates, the assayer floors, the bench measures, the exchange distributes, the fair certifies.
