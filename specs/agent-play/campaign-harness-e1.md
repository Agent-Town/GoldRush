# Campaign Harness — Epoch 1 (the provable first step)
### Status: DRAFT 2026-08-14 · attended session · the first slice of the continuous-campaign benchmark

## Why (owner directives, verbatim)
Owner, 2026-08-14: *"I think the AI should also start in epoch 1 and be able to beat that, then continue with the other epochs."* And, on the mechanism: *"normally it would work with a profile/user profile?"* — **yes.** The benchmark becomes a CONTINUOUS CAMPAIGN: an agent starts at E1, plays its contract DAG carrying a persistent PROFILE (the same machinery a human's profile uses), progressing exactly as a human does. "Assumes-progression" maps (E2's railcar, etc.) then become winnable **because the agent arrives progressed** — no rebalancing, no cold-start shortcuts. This proved out from the railcar v2 measurement (cold-start hero dies wave 7 vs a wave-12 railcar, 185/wave pressure deficit) — the map isn't broken, it assumes an E1-earned build.

**This spec is E1 ONLY.** E1 is 100% headless-admitted today (its whole DAG runs), so an E1 campaign proves the entire profile-threading mechanism *before* the per-epoch engine build-out (Layer 2) needed for E2+.

## Verified ground (scout 2026-08-14 — reuse, don't reinvent)
- Progression is profile-scoped localStorage (`gr.profile.v2.<id>.<key>`, `src/game/ProfileStorage.ts`). What actually persists (NOT gold/drafted-upgrades — those are per-run RAM, reset every `resetRun()`): **MetaProgress** (`gr.meta.v1`; science/territory/hero/agent tracks; funds megaprojects + `scienceNNN` unlocks + *is* E1's research pool), **Medals** (`gr.medals.v1`; baronBeaten, rocketCartCaptured), **ResearchState** (`gr.research.<epoch>.v1`; nodes gate upgrade eligibility, `Upgrades.ts:251`), **Scoreboard** (`gr.scores.v2`; drives the unlock chain), **megaproject state** (`gr.megaprojects.v1`), **active-epoch pointer** (`gr.activeEpoch.v1`).
- The headless sim today boots ONE contract **profile-less**: `HEADLESS_META_STORAGE` is a null stub (`HeadlessContractSim.ts:114`) — every progression read returns empty, every write is discarded. Each run is a cold start; that is the whole bug.
- **Reuse candidates (verified):** `packActiveProfile`/`unpackProfile` (`src/game/ProfileTransfer.ts:64-83` — the browser's "pack the ledger" feature; the exact CampaignState blob shape); the storage-injectable signatures on `Medals`/`MetaProgress`/`ResearchTree`; `contractUnlockStatus()` (`src/meta/ContractUnlock.ts` — pure, storage-driven — picks the next legal leg); `stableHash`/`fnv1a32` (`src/mp/LockstepClient.ts:967`); pinned per-leg seeds (`assets/contracts/bench-seeds.json`).
- **Global-singleton hazard:** `Scoreboard.ts`, `ContractFamilies.ts`, `Megaproject.ts` read `globalThis.localStorage`/`window.localStorage` directly (no injectable param), so a campaign needs its own process with a polyfilled `globalThis.localStorage`.

## Laws
1. **Profile is the progression** — carry the game's own profile state; invent no separate progression schema. Reuse `ProfileTransfer`'s shape.
2. **One process per campaign** — install a `FakeStorage` as `globalThis.localStorage` **and** `globalThis.window.localStorage`; no concurrent campaigns share a process.
3. **Replay-truth preserved** — the per-leg `eventLogHash` stays byte-for-byte as-is (still verifiable from `{contractId, seed}` + the leg-start CampaignState). The campaign ADDS hashes; it never changes the per-leg contract or the single-contract `gr-sim.mjs` path.
4. **Legal legs only** — pick each next leg via `contractUnlockStatus()` against the CARRIED state (E1's DAG defines order), never a hardcoded sequence.
5. **E1 only, no Layer 2** — touch NO E2+ engine wiring. E1 needs none (its Baron is beaten with E1 weapons, as codex-sol proved).

## Slices (each ends in a checkpoint + its gate)
1. **Inject a profile into one headless run.** A ~15-line in-memory `FakeStorage` (`getItem/setItem/removeItem/key/length`) installed as `globalThis.localStorage` + `globalThis.window.localStorage`; a new additive `HeadlessContractSim` constructor option threads it into `RunManager`'s `storage` (replacing the `HEADLESS_META_STORAGE` stub — default unchanged). **Gate:** a run booted with a pre-seeded FakeStorage (e.g. one research node taken) demonstrably READS that state (upgrade eligibility widens accordingly); a run with empty FakeStorage matches today's cold-start behaviour byte-for-byte (`eventLogHash` unchanged). No loop yet.
2. **Progression persists across two legs.** Capture a completed leg's end profile-state via `packActiveProfile(fakeStorage)`; inject it as the next leg's start via `unpackProfile`. **Gate:** play `the-claim`, then boot `e1-dry-gulch` — the secured-claim + any research from leg 1 is present in the FakeStorage at leg-2 boot (asserted by reading it between legs), and leg 2's `contractUnlockStatus()` reflects leg 1's result.
3. **The E1 campaign runner.** New `scripts/gr-sim-campaign.mjs` (sibling to `gr-sim.mjs`, `node:test`/`spawn` conventions from `gr-sim.test.mjs`): drives E1's DAG in one process, picking each next legal leg via `contractUnlockStatus()` against the carried state, until E1's terminal (Baron secured, or no legal leg remains). A deterministic scripted player plays each leg (reuse the Baron-campaign `player.mjs` pattern). **Gate:** a full E1 campaign run completes — the agent earns ≥6 science + 2 secured claims across the DAG, UNLOCKS and reaches `e1-baron` carrying its research (and, on beating him, the Baron medal appears in the carried profile). One artifact per leg + one campaign artifact.
4. **Verification + resumable checkpoint.** Per-leg `eventLogHash` unchanged; ADD a leg-boundary campaign-state hash (`stableHash(CampaignState)`) and a whole-campaign hash-chain (`stableHash` of the ordered `{contractId, seed, eventLogHash}` list, chained leg-to-leg, mirroring `RunTape.ts`'s id derivation); write the `CampaignState` JSON (ProfileTransfer envelope shape) after every secured leg as a resumable checkpoint. **Gate:** two runs of the same campaign (same seeds, same player) produce byte-identical whole-campaign hashes; a killed run resumes from the last checkpoint instead of leg 1.

## Integration map
NEW / additive: `scripts/gr-sim-campaign.mjs`; a `FakeStorage` module; one additive `HeadlessContractSim` constructor option (accept a real storage; default = today's stub, so the single-contract path is untouched). REUSE unchanged: `ProfileTransfer.ts`, `ContractUnlock.ts`/`contractUnlockStatus`, `stableHash`, `bench-seeds.json`, the browser progression modules (via the profile). UNTOUCHED: `gr-sim.mjs`'s single-contract path + its `eventLogHash` contract; ALL E2+ engine code (Layer 2 — a separate, sequenced effort); every gameplay balance value.
