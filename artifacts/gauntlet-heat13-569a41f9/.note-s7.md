
## 7. The rig — what changed from heat 12, and why

All scripts live beside this note; each header cites its own change.

| script | change |
|---|---|
| `probe-driver.mjs` | **New shape.** Heat 12's probe replayed a prior verified reel to prove sameness. Heat 13's takes `--filter-retired`, which drops `MOVE_TO`/`HOLD`/`FALLBACK_IF` from every array and changes nothing else, so the SAME reel can be run twice — once to be refused (the grammar proof) and once to verify (the engine proof). It also records surprises and the sim's stderr, which is where a refusal actually lives (F-HEAT13-1). |
| `verbcheck.mjs`, `refusal-visibility.mjs` | **New.** The first loads the door's own `validateStandingOrders` through vite and reports which of a reel's arrays the landed door refuses and with what message — turning a mute `bad_payload` into a named predicate. The second measures whether a refused array is visible to a rider that reads only stdout. It is not; that is F-HEAT13-1. |
| `make-charter.mjs` | The per-map mechanic table is replaced by **one** era-pin quotation (`rider-parity-grammar`, all stages) that applies to every map, with heat 12's mechanic lines appended where they still apply. New stakes: `re-ride` (your row was retired, not beaten) and `open-question` (the owner's desk is waiting on this map). A new **GRAMMAR** paragraph publishes the three removed verbs, the wholesale-refusal semantics and the operator's own pre-ride measurement — because the rider's notebook is 60 generations of the old grammar, and a rider that plans in it produces nothing at all (F-HEAT13-1), which is not a fair test of anything. Heat 12's two view traps (F-HEAT12-7) and the per-entry byte arithmetic (F-HEAT12-2) are published for the same reason. |
| `build-submission.mjs` | `harness: heat13-operator`; probe identity `Heat 13 Grammar Probe` on its own `anonId` (so probe POSTs never spend the rig's rate-limit budget — F-HEAT12-8). Everything else — the canonical bench-seed registry, the rotation-seed refusal by construction, the unsecured-tape refusal — is heat 12's and unchanged. |
| `receipts-delta.mjs` | **Bug fix.** The live board row is FLAT (`model`, `harness`, `harnessVersion`, `reel.id` at top level; **no `stack` wrapper and no `engineHash` at all**). Heat 12's reader looked only under `stack`, so every row it recorded read `model: null, harness: null` — its receipts files cannot tell one species from another. Heat 13 reads both shapes, and adds a `heat13Rows` count per contract so the delta can name its own rows. |
| `run-queue.sh` | Takes the queue file as an argument (a second block follows the first without editing the script), and runs a **disk guard** before every ride: under 700 MiB free it halts rather than half-write a ride's evidence. F-HEAT12-3 was live when this heat started — 4.4 GiB free on a 3.6 TiB disk. |
| `wait-queue.mjs` | **New.** A bounded, read-only progress waiter, so the operator watches the queue without polling it by hand every minute. |
| `ride-one.mjs`, `land-ride.mjs`, `finish-ride.mjs`, `matrix-row.mjs`, `notebook-append.mjs`, `poll-verdict.mjs`, `publish-submission.mjs`, `harness-digest.mjs`, `repoll-verdicts.mjs`, `launch-queue.mjs` | Heat 12's, with the arena, era hash, workspace root and harness id re-pointed. **All of heat 12's cures are kept and all of them earned their keep**: the tape read by its own `id` from its own JSON (F-HEAT11-2), the notebook/matrix appends inside the driver, the queue in its own process group, `poll-verdict` never writing the string `undefined`. |
