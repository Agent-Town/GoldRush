# F-1362-1 — the tree is dirty by design, and three fires blamed the wrong thing for it

**Fire:** s1362 · **Date:** 2026-08-02 · **Status:** MEASURED, no cure applied (deliberately — see §5)

## 1. The question

`logs/dashboard.html` was dirty at fire boot, as it has been at every fire boot for weeks.
s1358, s1360 and s1361 each committed it with a message attributing the regeneration to
**their own ledger-guard run** — e.g. `9d5aaf22 (archive: pruned by the A3 rewrite)` *"commit the blocked-seen state and dashboard
regenerated by my own ledger-guard run"*. F-1300-4 mandates that battery as every fire's LAST
act, so if it really did dirty tracked files, the mandated final act would be self-defeating.
That was worth one command.

## 2. The battery does not write those files — refuted at source

`scripts/goal-tracker.test.mjs:130-145` is the **only** executing caller of `dashboard-gen.sh`
in `test:ledger-guards`. It runs the script inside `fs.mkdtempSync(...)` and redirects **all five**
side-effect paths:

```
GOLD_RUSH_DASHBOARD_OUT · GOLD_RUSH_GOAL_TREE_TMP · GOLD_RUSH_BLOCKED_SEEN
GOLD_RUSH_HEALTH_LOG    · GOLD_RUSH_ROOT
```

The other battery members that mention the generator (`blocker-panel-closed-guard.mjs:81`,
`.test.mjs:12`) read its **source text** to extract the panel's selection pipeline; they never
execute it.

**Tested at its own birth commit, not just today:** `git log -G GOLD_RUSH_BLOCKED_SEEN --
scripts/goal-tracker.test.mjs` returns exactly one commit — `3739892f` (2026-07-16,
`runner(lane-b): goal-tracker-dashboard.md`). The redirect has been there since the guard was
born, **weeks before** all three claims. The attribution was never true.

## 3. The real writer

A launchd job, `com.goldrush.dashboard`, whose plist is tracked in the repo at
`scripts/com.goldrush.dashboard.plist`:

```
program        = /bin/bash scripts/dashboard-gen.sh
run interval   = 60 seconds
runs           = 33018
stdout/stderr  = logs/dashboard-launchd.log
```

Confirmed three independent ways: `logs/health.log` records `[dashboard] ... regenerated` at a
steady **68-second** cadence (01:41:12 · 01:42:20 · 01:43:28 · 01:44:36 · 01:45:43 · 01:46:51 —
60 s sleep + ~8 s runtime); the process was caught in flight at **pid 54292, ppid 1** (the launchd
signature — ordinary `ps` sampling misses it because each run lasts seconds); and `launchctl print`
names the plist above. There is no cron entry, no git hook (`.git/hooks` is LFS-only), and no
Claude hook involved.

## 4. What follows, and why it matters more than the churn

- **100% of the diff on a dry board is clock-derived.** Measured on the boot-time dirt: 38
  insertions / 38 deletions, every one of them the refresh timestamp, an `N minutes ago`, or a
  `blocked N min (tracked since first sighting)` counter. Zero board information.
- **No fire can end with a clean tree.** Whatever a fire commits, a tracked file is rewritten
  within ≤60 s. This is unconditional and permanent.
- **§2A's dirt signal is saturated.** "Uncommitted bookkeeping" exists to catch *attended*
  hand-work. It is guaranteed true at every boot regardless, so its information content is nil
  until a fire path-scopes past this one file.
- **The cost is visible in the ledger:** **148** commits touched `logs/dashboard.html` in the last
  three days; **28** of those subjects credit a guard run for the regeneration.

## 5. No cure applied, on purpose

The obvious cure — untrack the generated view — **contradicts a recorded decision**.
`.gitignore:48-54` ignores only the *scratch* render targets and documents the redirect
discipline in prose, keeping `logs/dashboard.html` deliberately tracked as "the live board".
Reversing that is a factory-policy call with RETENTION-LAW adjacency: owner/attended, not a
fire's drive-by (CLAUDE.md §7.3).

**Recommendation (one word from the owner):** leave as-is and accept the churn as the price of a
git-visible live board — *or* untrack `logs/dashboard.html` (it is 100% derivable from git +
ledger, so nothing is lost) and keep the tracked plist as the record. I recommend **leave as-is**;
the churn is cheap and the retention instinct behind tracking it is sound. The part actually worth
fixing is free: **stop crediting the guard battery in commit messages** — say "the 60 s
`com.goldrush.dashboard` job" instead.

## 6. The reusable half

s1361's rule was *verify your own claims, not only inherited ones*. This is that rule with a
sharper edge: **three fires attributed an effect to the last thing they happened to run.** The
guard battery was salient — freshly executed, mandated, top of mind — and the actual cause was a
daemon that had been running every sixty seconds the entire time, doing 33,018 identical things
while nobody looked at it. Proximity in time is not causation, and a cause that never announces
itself will lose the attribution contest to any cause that does.

The tell cost one `grep`: the guard's own env block names the redirect it performs.
