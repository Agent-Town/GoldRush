# Echo must own a snapshot of the visible building shapes

This supplements the read-only reference preflight. E6 regression remains live; no E7 implementation or browser rendering has begun.

The smallest useful change is at the existing snapshot boundary. `Game.ts` currently strips each live building to id/x/z before `EchoBossSystem.startMirror` calls `addCopy`. Build diagnostics already contain stable family/index, tier and position. Rotation and detailed geometry already exist in the render owners; reconstructing every building from another set of dimensions would create a second source of shape truth.

`Run3dPilot.ts` keeps actual full-tier objects in its private `instances` map, keyed by family/index. A narrow snapshot method can reach those objects. They carry the real node transforms (including compressed GLB transforms), palisade rotation/tint and lantern orientation. Its current public return only has update/dispose; access needs an explicit method, not scene traversal by position or a guessed object name. FULL does not include gold seams or rails by default; those are not live build diagnostics and must not become invented Echo buildings.

Fallback shapes belong to BuildSystem's existing pools. Most parts occupy one instance slot per building; palisade posts/rails use two, turret/beacon legs three, and sluice rails/legs two/four. Capture must expand the correct slots and retain their matrices. Do not infer slots per building from buffer capacity: LanternPostPool allocates twice maxCount while still using one slot per building. A whole pool clone would copy neighboring buildings, hidden zero-scale slots and signs/halos indiscriminately. Build ghosts, repair rings, health bars and wreck rubble are separate and must stay out.

A confirmed ownership hazard changes the design: `Game.fallbackToLiteRendering()` disposes Run3dPilot while the encounter may remain active. Run3dPilot disposes its template geometry/materials. An Echo copy cannot borrow those GPU resources indefinitely. It needs its own geometry (shared within the Echo's captured set where safe), its own signal materials, and reset/dispose cleanup. It must never mutate or dispose the source building's resources. Main Game teardown also disposes the source owners; apparent correctness in one intact frame is insufficient proof.

Preserve the simulation snapshot time, building/turret counts, mirror centers (-x, 34-z), approach factor .45, confidence/replay/pressure behavior and jar persistence. Local orientation must reflect the mirror transform, not merely relocate the original footprint. For shape grounding, preserve the source mesh's internal height offsets while moving the copy to local terrain; do not apply the old fixed box-height lift to arbitrary buildings.

Before implementation, capture a varied actual Relay Valley base at FULL and lite: rotated palisades, turret/beacon, low sluice/stockpile, lantern, and non-GLB fallback family where available. Inspect per-instance geometry and transforms against the source at the sampling moment. Test delayed GLB loading and tier demotion explicitly. Whether an already captured fallback silhouette should upgrade after a late load remains a presentation decision to settle from that evidence; changing simulation sampling time to hide loading is not acceptable.

The existing E7 test verifies two copied buildings and the novelty/capture behavior. Additional focused evidence must compare actual vertex/transform snapshots, source-resource immutability, both geometry ownership/disposal paths, terrain contact, mirrored orientation and readable desktop/mobile signal/jar views. Existing broad-suite success alone cannot establish those properties.

Orientation clarification: the current map is `(x, z) -> (-x, 34-z)`, whose X/Z linear part is negative identity. It preserves handedness and rotates by 180 degrees. A copied building's existing local yaw therefore receives an additional PI around Y; a single-axis negative scale would be the wrong transform. Keep mesh dimensions fixed while the authored approach interpolates the centers. Static corner checks, including a non-cardinal yaw, are in `orientation-preflight.json`; they do not replace the future rendered-geometry check.
